# 与“蜂巢教育 Agent”项目介绍的对齐

本仓库根据用户提供的 17 页《蜂巢教育 Agent 演示稿》和 Word 项目大纲设计。源文件作为设计依据保留在用户本机，未复制进仓库，以避免上传作者元数据、修订历史或尚未公开的比赛底稿。

## 当前实现对应关系

- “双减”后的自主学习需求：学生插件支持课中疑点记录、课后复习草案和课堂/家庭 Agent 衔接。
- “学生看不懂、教师做不动、工具连不起来”：把学生流程和教师流程分别封装为小型 MCP 插件，由 DSH 统一挂载。
- “讲解—演示—练习—反馈”：当前实现讲解/演示准备与反馈衔接接口；练习题生成与真实学习评价暂不实现，避免在无题库和审核系统时形成错误承诺。
- “教师目标—生成—审核—发布”：教师插件可以草拟计划、排队素材任务并打开审核门，但绝不自动发布。
- “模型做规划、专业工具做生产”：ComfyUI、3D 与文档任务使用 `executionMode=stub` 和明确的适配器名称，不伪造生产结果。
- “三类数据、四条原则”：只使用匿名 fixture；来源、AI 标识、教师审核和审计接口贯穿工具输出。
- “先单点验证，再扩展集群”：仓库只实现两个插件和一个高中物理样例，不搭建完整三端应用或商业平台。

## 从前期讨论复用的部分

- DeepSeek Harness 0.1.0-rc.5 的 Cordis overlay 接入方式。
- MCP SDK 真实工具注册与内存传输测试。
- 高中物理“电磁感应与楞次定律”固定演示场景。
- 课堂疑点到课后个人 Agent 的衔接思路。
- 来源可追溯、匿名 fixture、教师最终确认、不泄露题目答案等证据边界。

## 未实现且只保留接口的部分

- 学生端、教师端和课堂端 UI。
- 登录、班级、监护人授权和学校组织空间。
- 数据库、对象存储、消息队列和跨进程共享状态。
- 真实大模型、联网检索、教材知识库、ComfyUI 和 3D 生成服务。
- 计费、插件市场、私有化部署和真实教学效果评估。
